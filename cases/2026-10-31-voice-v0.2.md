# 2026-10-31 语音 v0.2：语气标记真的变成韵律 + 引擎可切换

## 现象

v0.1.0 上线后，语音条能发、能听，但和「像人」差一截：

1. **语气标记是装饰**：预设让 agent 每条语音写 1~2 个 `[笑] [叹气] [小声]`，
   但服务一律把它们换成逗号——听感上和没写标记一模一样。提示词里承诺的表达通道是假的。
2. **换引擎要动代码**：ADR-0001 写着「换引擎只换壳」，可壳里写死了 `edge_tts`，
   想接火山/CosyVoice 得改 `server.py`。
3. **高频短语气反而最慢**：「嗯」「诶」「在的」出现频率最高（一条 0.3~1.4 秒），
   却每次都要现场等微软 1.3~2.5 秒。

## 根因

不是 bug，是 v0.1.0 的设计边界：

- v1 的 `clean_text()` 只做「标记 → 逗号」。Edge 的 WSS 接口**不接受 SSML**
  （传 `<prosody>` 会被当正文念出来），所以「用标签语义改韵律」在单次请求里做不到。
- 能改语速/音高/音量的只有 edge-tts 客户端参数（`rate` / `pitch` / `volume`），
  它们是**整段音频的全局属性**，一条请求只能有一组。
- 于是「一段话里有两种情绪」就必须拆成多次合成——这是 v1 架构里没有的那一层编排。

## 影响面

- 只影响语音：聊天、B站、记忆链路零改动。
- 改动文件：`deploy/voice-edge/server.py`（重写）、新增 `engine.json` / `prewarm.py` / `selftest.py`、
  `voices.json`（加 `prewarm` 清单）。
- 契约**一个字没改**：SurfCore / 桥接 / 预设都不用动，`X-Duration-Ms`、`X-Cached`、裸 PCM 全保留。
- 不碰密钥：`engine=openai` 的 key 只从环境变量读。
- 失败面：合成失败仍返回 503 → 桥接 502 → agent 改打字，不静默假装。

## 修法

**韵律（对比三种）**

| 备选 | 为什么不选 |
|---|---|
| 只用标点停顿 | 就是 v1，做不到语速/音高 |
| SSML | Edge 不支持，会被念出来 |
| 后期 ffmpeg 变速变调 | 变速连带音高失真，段间拼接不自然 |
| **分段合成再拼接（选中）** | 唯一能同时改语速/音高/音量/停顿且不掉音质的方案，换引擎也照样成立 |

实现：`parse_segments()` 按 `[标记]` 切段，标记管**它后面那句话**的情绪，停顿插在那句话之前
（真人先吸一口气再说话）；`PROSODY` 表把 21 个标记映射到 `rate/pitch/volume/pauseMs`；
每段用各自参数合成 mp3 → ffmpeg 转 24k 单声道 WAV → 用 `wave` 按停顿拼接 → 整条写缓存。

**引擎（对比两种）**

| 备选 | 为什么不选 |
|---|---|
| 写死 edge | 违背 ADR-0001 |
| **`engine.json` + 环境变量（选中）** | 一行切换；openai 兼容层能套火山/CosyVoice/自建 |
| 每个引擎独立进程 | 也能用（SurfCore 有 local/cloud 双路由），但不妨碍先有统一入口 |

**缓存**：`prewarm.py` 把 `voices.json` 的 `prewarm` 清单先合成进缓存；
`selftest.py` 把契约做成 14 项断言，改完就跑。
