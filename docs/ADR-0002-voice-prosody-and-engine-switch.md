# ADR-0002：v2 把语气标记做成韵律 + 引擎可切换

- 状态：已采纳（2026-10-31）
- 决策者：项目主人 + 实施者
- 关联：ADR-0001（引擎选 Edge TTS）、ROADMAP v0.2

## 背景

v0.1.0 的语音链路能出声，但「像人」只做到一半：

1. **语气标记是装饰**：`[笑] [叹气] [小声]` 一律被换成逗号。预设让 agent 每条语音写 1~2 个标记，
   但听起来和没写一模一样——等于提示词里承诺了一个不存在的表达通道。
2. **换引擎要改代码**：`server.py` 里写死 `edge_tts`，ADR-0001 说「换引擎只换壳」，
   但实际上壳里还是只有一层 edge。
3. **短语气每条都要现等**：「嗯」「诶」这种 0.3 秒的反应，现场合成要 1.3~2s，
   而它们恰恰是出现频率最高的。

## 选项

**韵律怎么实现**

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 只用标点/停顿 | 标记 → 逗号 / 句号 | 做不到语速音高，v1 就是它 |
| B. **分段合成再拼接（选中）** | 按标记切段，每段用各自的 rate/pitch/volume 合成，段间插空白 | 要多跑几次合成（一条 2 段 ≈ +1.3s） |
| C. SSML | `<prosody rate=…>` | Edge 的 WSS 接口不接受 SSML（会被当正文念） |
| D. 后期变调 | 一条合成完再 ffmpeg 伸缩/变调 | 变速会连带音高失真，拼接处也不自然 |

选 B：唯一能同时改「语速 + 音高 + 音量 + 停顿」且不引入音质的方案；换引擎后照样成立，
因为分段是 HTTP 层的编排，跟后端是谁无关。代价（多一次网络往返）在 2 段以内可接受，
而且真正高频的短语气走预热缓存，根本不冷启动。

**引擎怎么切**

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 写死 edge | 现状 | 违背 ADR-0001 的可替换承诺 |
| B. **engine.json + 环境变量（选中）** | `engine: edge / openai`，openai 走 `/audio/speech` | 多一层间接，配置有一处要维护 |
| C. 每个引擎一个独立进程 | 8765 edge / 8767 火山，SurfCore 用 `tts.route` 切 | 也能用，但两个引擎要各写一份壳；本地/云双路由是 SurfCore 的维度，不是引擎的维度 |

选 B，同时保留 C 作为「真的同时想要两个引擎」时的选项（两者不冲突）。

## 决定

1. `server.py` 升到 v2：按语气标记切段，`PROSODY` 表把 21 个标记映射到 rate/pitch/volume/pause；
2. `engine.json` 决定引擎，密钥只从环境变量读；
3. `prewarm.py` 预热高频短句（`voices.json` 的 `prewarm` 清单）；
4. `selftest.py` 14 项契约自检，改完就跑，不靠耳朵验收；
5. 契约**一个字没改**：桥接零改动，`X-Duration-Ms` / `X-Cached` / 裸 PCM 行为全部保留，
   只多了 `X-Engine` / `X-Segments` 两个响应头。

## 代价

- 带标记的句子会多花 1~2 次合成（每条 ≤3 段，实测 +1.3s/段，冷）。
- 时长会变长：`[叹气]` 慢 10% + 350ms 停顿 ⇒ 一条 3 秒的句子可能 3.6 秒。
  这是语气的本意，但如果 agent 滥用标记就会显得拖。缓解：预设里限「一条 1~2 个标记」。
- `engine=openai` 这条路**尚未用真实云端密钥验证过**（只有契约和代码），
  接火山/CosyVoice 时要按 ADR-0001 的表格留一份实测。

## 后续

- 真听感验收还没做：盲听 10 条，能不能分出「同一个人的语气」。
- 如果 `[笑]` 还是不够像，正解是语音库补一条真录音/真笑声（`audio/`），而不是继续调参数。
